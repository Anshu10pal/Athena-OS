# Voice stack. MERGED IN from the former requirements-voice.txt, 2026-09-03.
#
# It used to be an optional extras file, and that produced exactly the failure
# mode an optional extras file produces: three modules (voice.py, oratory.py,
# communication.py) imported these libraries at request time, none of them were
# installed, and every voice endpoint in the application returned 501 or
# silently degraded -- discoverable only by calling the endpoint. The baseline
# in docs/voice-known-issues.md records all five.
#
# The trade is deliberate: install size and cold-start cost, in exchange for the
# app either booting with voice working or failing at BUILD, never at a user's
# first request.
faster-whisper==1.1.1

# edge-tts WAS HERE and is gone as of Phase 6, 2026-09-03. It was the original
# primary TTS: a websocket call to a Microsoft endpoint, which made every spoken
# response depend on a network round-trip, broke behind the corporate proxy
# (docs/TROUBLESHOOTING.md carried two separate sections about it), and sent
# every utterance to a third party. Kokoro replaced it as primary in Phase 4 and
# the removal waited until Phase 6 measurement confirmed no endpoint regressed,
# so weight-baking had a rollback path that did not depend on the same weights.
#
# It is not coming back as a fallback. A network fallback under a local-first
# primary is the configuration where an offline guarantee silently stops
# holding, which is the whole class of defect Phase 5 closed.
# 1.7.0, NOT the 1.2.0 that was pinned in the old extras file. That pin was
# UNINSTALLABLE on this runtime: piper-tts 1.2.0 requires
# piper-phonemize~=1.1.0, which publishes no distribution for Python 3.12
# (every version caps at <3.12) and this project pins python-3.12.8. So the
# Piper TTS fallback in voice.py did not merely lack a voice file -- it could
# never have been installed here at all, which is why the extras file being
# optional hid a dead pin for as long as it did.
#
# 1.7.0 dropped the piper-phonemize dependency: it needs onnxruntime (already
# present via fastembed) plus pathvalidate, so the transitive graph is SMALLER
# than the broken pin's would have been. The synthesize() API changed across
# this range; the call site was updated in Phase 4 and now uses
# synthesize_wav().
#
# Piper is now the ONLY fallback, which raises the cost of its missing voice
# file (VKI-5) from "third choice ships weightless" to "the sole fallback ships
# weightless". Filed, not fixed here: scripts/fetch_models.sh fetches it, and
# engine_status() reports it as unready rather than pretending.
piper-tts==1.7.0
soundfile==0.13.1

# Kokoro TTS. `kokoro-onnx`, NOT the `kokoro` PyPI package -- that one is
# torch-based and pip resolves it to cuda-toolkit, nvidia-cublas, nvidia-cudnn
# and nvidia-cufft, which is disqualifying under this project's CPU-only
# constraint before image size is even discussed. kokoro-onnx runs on the
# onnxruntime already present for FastEmbed and pulls four small packages.
#
# espeakng-loader ships libespeak-ng INSIDE the wheel, so phonemisation needs
# no system package -- that is what keeps Windows dev parity without WSL.
#
# Model weights are NOT pip-installed and NOT committed: 88 MB (int8) + 26 MB
# voices. Phase 5 bakes them into the image; locally, run
# scripts/fetch_voice_models.sh.
kokoro-onnx==0.6.1
